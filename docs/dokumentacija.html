1. Pregled Projekta

1.1 Namena i opis

Reciklaža.rs je B2B web platforma za kupovinu i prodaju otpada u Srbiji. Platforma omogućava kompanijama i preduzetnicima da objavljuju oglase za otpad koji žele da prodaju ili predaju na reciklažu, kao i da pronalaze sakupljače otpada u svojoj blizini.

Sva komunikacija između korisnika odvija se isključivo unutar platforme putem ugrađenog sistema za poruke — telefonski brojevi i email adrese korisnika nisu javno vidljivi, čime se obezbeđuje privatnost i bezbednost podataka.

Platforma je vlasništvo preduzetnika PORT 22 Mihailo Đorđević PR (PIB: 111988991, MB: 65790777) koji deluje isključivo kao posrednik — ne poseduje otpad, ne naplaćuje proviziju i ne učestvuje u transakcijama između korisnika.

1.2 Tipovi korisnika

🏭 Generator otpada

  • Firme koje proizvode otpad
  • Mogu postavljati oglase
  • Dodaju slike oglasa
  • Komunikacija sa sakupljačima

🚛 Sakupljač otpada

  • Firme koje sakupljaju/recikliraju otpad
  • Pregledaju oglase i kontaktiraju
  • Ne mogu postavljati oglase
  • Komunikacija sa generatorima

🔐 Administrator

  • Odobrava/odbija registracije novih korisnika
  • Pregledava i modifikuje sve korisnike i oglase
  • Kreira korisnike i oglase u ime firmi
  • Šalje broadcast poruke svim korisnicima
  • Pristup admin panelu na /admin

5. Autentikacija i Autorizacija

Koristi se NextAuth.js v5 sa Credentials providerom i JWT strategijom. JWT token se čuva u HTTP-only cookie-ju, bez potrebe za tablelom sesija u bazi.

5.1 Tok registracije

Korak 1: Izbor tipa → GENERATOR ili COLLECTOR
     ↓
Korak 2: Unos podataka firme → naziv, PIB, adresa, opština, kontakt osoba, telefon
     ↓
Korak 3: Upload dozvola → minimum 1 fajl (PDF/JPG/PNG, max 10MB)
           → Fajlovi se čuvaju na: public/uploads/permits/{userId}/
     ↓
Korak 4: Email i lozinka → minimum 8 karaktera
     ↓
POST /api/register:
  - Validacija PIB-a (9 cifara)
  - Provera duplikata (email, PIB)
  - bcrypt hashovanje lozinke (salt rounds: 12)
  - Kreiranje User-a (emailVerified: false, verified: false)
  - Čuvanje dozvola u Permit tabeli
  - Generisanje 6-cifrenog koda, slanje na email putem Resend-a
  - Kreiranje AdminNotification za admina
     ↓
/verifikacija-emaila → korisnik unosi 6-cifreni kod (važi 15 min)
     ↓
POST /api/verify-email → emailVerified: true
     ↓
/cekanje-odobrenja → korisnik čeka admin odobrenje
     ↓
Admin odobrava u /admin/korisnici → verified: true
  → Šalje se email obaveštenje korisniku da je nalog odobren
     ↓
Korisnik se može prijaviti

5.2 Tok prijave

POST /api/auth/callback/credentials
  ↓
Provere u authorize() funkciji (src/lib/auth.ts):
  1. Nalazi korisnika po emailu
  2. bcrypt.compare(password, passwordHash)
  3. if (!emailVerified) → throw Error('EMAIL_NOT_VERIFIED')
  4. if (!verified && !isAdmin) → throw Error('NOT_APPROVED')
  5. Uspešno → JWT token sadrži: id, email, userType, companyName, verified, isAdmin
  ↓
JWT token → HTTP-only cookie (SameSite=Lax)
  ↓
Middleware (src/middleware.ts) proverava JWT na svakom zahtevu

5.3 Uloge korisnika

UlogaUslovDozvoljene akcije
GostNeprijavljen korisnikSamo: /prijava, /registracija, početna stranica
GeneratoruserType=GENERATOR, verified=trueSve + postavljanje oglasa

  • Izmena bilo kog oglasa (sve stavke)

  • Brisanje oglasa

🔔 Obaveštenja

  • Automatska notifikacija pri novoj registraciji
  • Automatska notifikacija pri novom oglasu
  • Crveni badge sa brojem nepročitanih u sidebar-u

📢 Broadcast poruke

  • Slanje poruke svim korisnicima odjednom
  • Poruke stižu kao direktne poruke u inbox
  • Potvrda sa brojem primalaca

10.2 Admin nalog

11. Bezbednost

#MeraImplementacija
1Zaštita ruta (Middleware)NextAuth authorized() callback u src/middleware.ts proverava JWT token i preusmerava neovlašćene korisnike
2Security HeadersX-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy konfigurisani u next.config.ts
3Rate LimitingIn-memory implementacija u src/lib/rate-limit.ts. Limiti: auth 5/min, API 30/min, upload 10/min, poruke 20/min
4Input Validacija (Zod)Sve forme i API endpoint-i validiraju input na klijentu (UX) i serveru (bezbednost)
5SQL Injection zaštitaPrisma koristi parametrizovane upite — direktno SQL ubacivanje je nemoguće
6Input Sanitizacijasrc/lib/utils/sanitize.ts uklanja HTML tagove, JavaScript protokol i event handlere iz korisničkog unosa
7Upload ValidacijaProvera MIME tipa, veličine fajla i broja fajlova pre čuvanja

12.4 Proces deploy-a (ažuriranja)

Pri svakoj novoj verziji koda pokreće se deploy skripta /root/deploy.sh:

ssh root@152.239.119.45 "/root/deploy.sh"

Skripta automatski:

  1. Povlači izmene sa GitHub repozitorijuma (git pull origin main)
  2. Instalira nove zavisnosti (npm install)
  3. Primenjuje izmene šeme baze (npx prisma db push)
  4. Pravi production build (npm run build)
  5. Restartuje aplikaciju sa novim .env varijablama
Napomena o .env: Fajl .env se NE čuva u git repozitorijumu. Sve izmene env varijabli na serveru se rade direktno: ssh root@152.239.119.45 "nano /var/www/reciklaza-rs/.env", nakon čega je potrebno pokrenuti deploy skriptu.
